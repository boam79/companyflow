# 개발 백로그

한 번에 한 작업만 실행한다. 성공 기준을 확인한 뒤 사용자 수동 확인을 받고 다음으로 간다. 회사·세션·모듈·RLS를 만지면 [tenants.md](tenants.md)를 지킨다.

원문 단계: PRD 11.1. 해석: [analysis.md](analysis.md).

## T0. 문서 기반 합의

- 성공 기준: `DOC/`에 PRD·분석·계획·원격 규칙이 있고, GitHub origin이 `https://github.com/boam79/companyflow.git`이다.
- 상태: 완료. origin `https://github.com/boam79/companyflow.git` 의 `main`에 문서가 있다.

## T1. 저장소·스택 잠금

- 상태: 완료. Vite 한글 셸, Vitest, 프로덕션 빌드 통과. HTTPS E2E는 배포 URL 후.

## T2. 중앙 운영 골격

- 상태: 완료. 전용 `companyflow` 프로젝트, RLS, `create_company`, 운영자 계정.

## T3. 로컬 원본 엔진

- 상태: 완료. SAH Pool OPFS로 지정 Chrome에서 사용 가능 확인.

## T4. 회사 생성 → 지정 PC 초기화 → 사용 시작

- 상태: 완료. 본사(HQ01) 생성, 지정 PC SAH Pool, 기본 설정 복사.

## T5. 기준정보 + 최소 설정 레이어

- 상태: 완료. `/master` 에서 총무 등 기준정보 확인. 부서·직원·품목·거래처·창고·필드, operation_id.

## T6. 구매·재고 공통 명령

- 성공 기준: 요청·발주·수령·직접 입고·출고·반출·정정·이동·실사. 원자성·`operation_id` (AC-05~12, AC-25~26).
- 검증 시나리오: 복사용지 발주 10 → 수령 6+4 → 반출 3 → 반납 1 → 현재고 8. 이동 후 회사 합계 8.
- 상태: 완료. 지정 Chrome에서 수령·반출·반납·이동 수불부 확인. 실제 반출이 4라 회사 합계는 7, 본사 5, 부속 2.

## T7. 자산·입퇴사·문서·통계

- 성공 기준: AC-04, AC-13, AC-23. AC-14 통계 메뉴·Excel은 사용자 요청으로 완료 조건에서 제외.
- 상태: 완료. 지정 Chrome 본사(HQ01) 원본에서 입퇴사 지급·회수, 이관, 빈 QR, QR 상세, 비품/자산 발주 구분, 책상 수령 자산화, 복사용지≠자산을 확인했다. `/reports`는 되돌리지 않음.

## T8. 계약 직접 등록 + OCR 어댑터

- 성공 기준: 원본 보존, 사용자 확인 후 초안 (AC-15~16). 품질 미통과 시 자동 추출 OFF.
- 상태: 완료. 지정 Chrome 본사 `/contracts`에서 OCR 확인·초안·원본. CON-03 신뢰도 0.5 미만은 칸을 채우지 않음.

## T9. Relay·백업·실권한 검증

- 성공 기준: 키·암호·복구가 확정된 뒤에만 활성화. AC-20~22, AC-34.
- 상태: 완료. D-35 ECDH·PBKDF2. 지정 Chrome 본사에서 수신 키·암호화 묶음. HTTPS E2E 게스트 백업 잔재 0.

## CON-07. 계약 기한 알림

- 성공 기준: 검색, 종료 60일 안 만료 예정, 기한 알림. 거래처 링크. 같은 이름·상대는 새 초안 안내(개정 이력 표는 후속).
- 상태: 완료. `/contracts` 만료 예정 탭. `/stock` 재고 부족. `/people` 기한 지남. 홈 표지는 유지.

## CON-06. 유사 계약 신규·개정

- 성공 기준: 같은 파일 해시는 한 번만. 같은 이름·상대는 사용자가 새 초안인지 개정인지 고른다. 개정 이력을 보여 준다. 거래처·발주를 연결한다.
- 상태: 완료. 개정은 이전 초안 스냅샷. 건수 0 이력은 숨김.

## CON-04. 필드별 OCR 근거

- 성공 기준: 칸마다 원문·페이지·인식 신뢰도·사용자 확인 값을 남긴다. 인식 신뢰도와 확인한 값을 구분한다. 근거 0은 숨긴다.
- 상태: 완료. bbox 점프는 이 묶음에 두지 않음.

## CON-08. OCR 실패 재시도·원본 보존

- 성공 기준: 원본·OCR 텍스트·추출 결과는 로컬. 실패 시 다시 읽기·직접 입력. 원본을 지우지 않는다.
- 상태: 완료. 얇은 처리 중·확인 필요·실패 안내. `/reports`는 두지 않음.

## CON-05. 확인 후 초안

- 성공 기준: 원본과 추출값을 사용자가 확인한 뒤에만 초안 한 건. OCR만으로 체결하지 않는다. 파일 없으면 직접 입력.
- 상태: 완료. 읽는 중 그만 읽기.

## CON-02. 원본 형식·용량·페이지 한도

- 성공 기준: PDF·PNG·JPEG. 회사 설정에서 용량·OCR 쪽 수를 정한다.
- 상태: 완료. 기본 8MB·2쪽.

## PUR-01. 구매요청 (결재 없음)

- 성공 기준: 요청자·부서·필요일·목적·첨부와 품목별 수량·단가·금액을 입력한다. 결재 없이 바로 열린다. 발주에 연결하면 원요청 잔량을 넘지 못한다. 제목 0은 숨긴다.
- 상태: 완료. 첨부는 PDF·PNG·JPEG 8MB. PUR-02 결재는 두지 않음.

## 하지 않을 것 (이번 제품 범위 밖)

다중 PC 공동 편집, 회계·급여·세무, 법적 전자서명, 재고 원가, 다중 단위·lot, 진행 업무 Template 이관, 앱 종료 중 외부 알림.
