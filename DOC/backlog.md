# 개발 백로그

한 번에 한 작업만 실행한다. 성공 기준을 확인한 뒤 사용자 수동 확인을 받고 다음으로 간다.

원문 단계: PRD 11.1. 해석: [analysis.md](analysis.md).

## T0. 문서 기반 합의

- 성공 기준: `DOC/`에 PRD·분석·계획·원격 규칙이 있고, GitHub origin이 `https://github.com/boam79/companyflow.git`이다.
- 상태: 완료. origin `https://github.com/boam79/companyflow.git` 의 `main`에 문서가 있다.

## T1. 저장소·스택 잠금

- 성공 기준: Vite + React + TypeScript + Tailwind + 잠금 파일. 한글 셸 화면이 빌드된다.
- 검증: 사용자 규칙상 localhost가 아니라 **배포 HTTPS URL**. 호스팅이 정해지기 전에는 빌드 성공과 문서화까지만 하고, 브라우저 E2E는 배포 URL 확보 후로 미룬다.

## T2. 중앙 운영 골격

- 성공 기준: Supabase Auth, 중앙 최소 모델, RLS. 운영 관리자만 회사 생성 (AC-31 골격).
- 일반 계정의 생성·자가 승격·미수락 초대 업무 접근을 차단한다.

## T3. 로컬 원본 엔진

- 성공 기준: SQLite WASM Worker + OPFS, 회사별 DB/파일 영역, 탭 잠금, 재실행 후 보존, 마이그레이션 실패 시 이전 상태 유지.

## T4. 회사 생성 → 지정 PC 초기화 → 사용 시작

- 성공 기준: AC-01, AC-32, AC-34.
- 기본 설정 복사만 수행한다. 설정 편집기 전체는 T5.

## T5. 기준정보 + 최소 설정 레이어

- 성공 기준: 부서·직원·품목·거래처·창고, `custom_fields` 저장. A/B 회사 라벨·필드 독립 (AC-02 최소).

## T6. 구매·재고 공통 명령

- 성공 기준: 요청·발주·수령·직접 입고·출고·반출·정정·이동·실사. 원자성·`operation_id` (AC-05~12, AC-25~26).
- 검증 시나리오: 복사용지 발주 10 → 수령 6+4 → 반출 3 → 반납 1 → 현재고 8. 이동 후 회사 합계 8.

## T7. 자산·입퇴사·문서·통계

- 성공 기준: AC-04, AC-13, AC-14, AC-23.

## T8. 계약 직접 등록 + OCR 어댑터

- 성공 기준: 원본 보존, 사용자 확인 후 초안 (AC-15~16). 품질 미통과 시 자동 추출 OFF.

## T9. Relay·백업·실권한 검증

- 성공 기준: 키·암호·복구가 확정된 뒤에만 활성화. AC-20~22.

## 하지 않을 것 (이번 제품 범위 밖)

다중 PC 공동 편집, 회계·급여·세무, 법적 전자서명, 재고 원가, 다중 단위·lot, 진행 업무 Template 이관, 앱 종료 중 외부 알림.
